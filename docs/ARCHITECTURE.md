# LMB trading venue: architecture and module contracts

This is the contract every module is built against. If code and this file disagree, this file wins
until it is changed deliberately.

## 1. What the system is

A single-region equities venue (limit and market orders, day-only, tick $0.01) built as a set of
**shards**. Each shard is a replicated deterministic state machine:

```
participants -> order gateways -> [ Raft input log -> risk + matcher -> event stream ] -> gateways (exec reports)
                                     ^        (one shard, Aeron Cluster)        |-> market data publisher
 feed handlers -> NBBO consolidator -+                                          |-> drop copy / Kafka / clearing
 control plane (scheduler, market ops, risk-budget allocator) ------------------+-> WORM archive, ClickHouse
                                                                                |-> shadow replayer
```

Rules that hold everywhere:

1. **The log is the only source of truth.** Everything that can change a book (orders, cancels,
   reference prices, halts, auction transitions, risk limits, timers) is a command in the shard's
   Raft log. Log order is priority order.
2. **The state machine is deterministic.** No wall clock, randomness, threads or I/O inside it.
   Time is the log entry's cluster timestamp. Replaying the log reproduces the event stream byte for byte.
3. **Output is gated on commit.** The matcher only sees committed entries (Aeron Cluster guarantees
   this), so no ack, fill or market data can leave before it is durable on a quorum. RPO is 0.
4. **Events are effectively-once.** Every event has a deterministic identity
   `(shardId, logPosition, eventIdx)` and a dense per-shard `eventSeq`. Delivery is at-least-once;
   consumers resume from the last `eventSeq` they processed and drop anything at or below it.
5. **No ordering guarantee across shards.** Mass cancels and halts are atomic per shard only.

Stack: Java 21, Aeron Cluster + Archive 1.54, Agrona, SBE, Artio (FIX), grpc-java, Maven.

## 3. Commands and events

Wire format is SBE, little endian, schema id 1 (`schemas/src/main/resources/sbe/venue.xml`; read it,
the field descriptions are part of this contract). A command or event on any transport is one SBE
message: `messageHeader` (8 bytes) followed by the body. Prices are integer cents; `Price` null is
`Long.MIN_VALUE`. Quantities are shares.

Commands: `NewOrder(1) CancelOrder(2) ReplaceOrder(3) MassCancel(4) ReferencePrice(10)
SymbolDefinition(11) SymbolStateCommand(12) RiskLimitUpdate(13) DayRollover(14)`.

Events: `ExecutionReport(101) Trade(102) BookDelta(103) SymbolStateChanged(104) AuctionUpdate(105)
ReferencePriceApplied(106) MassCancelDone(107) RiskLimitApplied(108) SymbolDefined(109)
CommandRejected(110) DayRolled(111) CommandApplied(120)`.

Every event body starts with `EventHeader` (use `io.lmb.common.Events` for allocation-free access):
`eventSeq` starts at 1 and increases by exactly 1 per event per shard; `eventIdx` restarts at 0 for
each log entry; `timestampNs` is the log entry's cluster time (epoch ns).

**Every log entry (command or timer) ends with exactly one `CommandApplied`**, even when the command
was rejected, was a dropped duplicate, or was malformed. It marks the batch boundary (consumers that
need atomicity, such as the market data publisher, act on it) and carries the hash chain defined in
`io.lmb.common.HashChain`.

### 3.1 State machine behaviour (`matcher-core`)

Identity and idempotency
- `orderId = (shardId << 48) | n`, `matchId = (shardId << 48) | m`, with n and m dense counters from 1.
- Dedupe key is `(firmId, clOrdId)` and covers NewOrder, CancelOrder and ReplaceOrder request ids.
  A repeated key with `possResend = TRUE` is dropped silently (only `CommandApplied` is emitted);
  with `possResend = FALSE` it is rejected with `DUPLICATE_CLORDID`. The table is cleared by `DayRollover`.

Symbol states (`SymbolState`)
- `PRE_OPEN`: no new orders (`SYMBOL_CLOSED`), cancels allowed.
- `AUCTION_CALL`: limit orders accumulate without matching, cancels and replaces allowed, market
  orders rejected (`MARKET_ORDER_NOT_ALLOWED`). An `AuctionUpdate(isFinal=FALSE)` is emitted whenever
  the indicative price or quantities change.
- `CONTINUOUS`: price-time priority matching.
- `HALTED`: new orders and replaces rejected (`SYMBOL_HALTED`), cancels always allowed, book retained.
- `CLOSED`: no orders; on entry all resting orders expire (`ExecType.EXPIRED`, `CancelReason.END_OF_DAY`).
- `REMOVED`: symbol leaves the shard; resting orders canceled with `SYMBOL_REMOVED`.
- Leaving `AUCTION_CALL` for `CONTINUOUS` or `CLOSED` runs the uncross first: the price that maximises
  matched volume, then minimises imbalance, then is closest to the reference price, then is lowest.
  All auction trades print at that one price (`isAuction = TRUE`, liquidity `AUCTION`), allocated by
  price then time. Then `AuctionUpdate(isFinal=TRUE)`.
- Allowed transitions: PRE_OPEN->AUCTION_CALL|CONTINUOUS|CLOSED, AUCTION_CALL->CONTINUOUS|HALTED|CLOSED,
  CONTINUOUS->HALTED|AUCTION_CALL|CLOSED, HALTED->AUCTION_CALL|CONTINUOUS|CLOSED, CLOSED->PRE_OPEN,
  any->REMOVED. Anything else: `CommandRejected(INVALID_STATE_TRANSITION)`.
- `SymbolStateCommand.effectiveTimeNs > 0` schedules a timer through `TimerScheduler`; the transition
  applies in `onTimer`. Pending scheduled transitions are part of the snapshot.

Order handling in `CONTINUOUS`
- Validation order for NewOrder: firm known and enabled, symbol known, symbol state, quantity
  (positive, multiple of lot, <= maxOrderQty), price (limit: positive, on tick, inside the band),
  dedupe, credit, position. First failure produces one `ExecutionReport(REJECTED)` with `orderId = 0`.
- Accepted: `ExecutionReport(NEW)` first, then matching. For each match: one `Trade`, one
  `ExecutionReport` for the aggressor (`TAKER`), one for the resting order (`MAKER`, `gatewayInTsNs = 0`).
  Trades print at the resting order's price. `BookDelta` for every price level whose total changed.
- LIMIT DAY remainder rests. IOC remainder is canceled (`IOC_REMAINDER`). MARKET never rests: it
  sweeps only prices inside the band and the remainder is canceled (`MARKET_COLLAR`, or the order is
  rejected with `NO_LIQUIDITY` if nothing was filled and the opposite side is empty).
  MARKET needs a reference price (`NO_REFERENCE_PRICE` otherwise).
- Price band: `[ref * (1 - bps/10000), ref * (1 + bps/10000)]` rounded inward to the tick. Checked
  at entry and on replace. Resting orders are not re-checked when the reference price moves.
- Cancel: `ExecutionReport(CANCELED, cancelReason=CLIENT)` with `clOrdId` = the cancel's id and
  `origClOrdId`. Unknown order: `CANCEL_REJECTED/UNKNOWN_ORDER`; already filled or canceled:
  `CANCEL_REJECTED/TOO_LATE_TO_CANCEL`. Cancel and replace must come from the owning firm.
- Replace: quantity decrease at the same price keeps time priority; a price change or quantity
  increase loses it (re-queued at the back, may match immediately). `newQuantity <= cumQty` is
  `INVALID_REPLACE`. Success: `ExecutionReport(REPLACED)`; the order is then known by the new `clOrdId`.
- No self-trade prevention.

Risk (per firm, per shard; limits arrive as `RiskLimitUpdate`)
- `creditUsed = notional of the firm's open orders (both sides) + |net traded notional today|`.
  A new order is rejected with `CREDIT_LIMIT` if it would push `creditUsed` over `creditBudget`
  (market orders are valued at the band edge they could reach).
- Position: per symbol, reject with `POSITION_LIMIT` if the worst-case position after the order
  (`net position +- open quantity on that side +- order quantity`) would exceed `maxPositionPerSymbol` in absolute value.
- A budget below current usage is accepted; it only blocks new orders. `enabled = FALSE` is a kill
  switch: new orders rejected with `FIRM_DISABLED`, cancels still work.
- `RiskLimitApplied` echoes the limits and `creditUsed` at that instant.

Other commands
- `MassCancel`: cancels matching orders in time-priority-independent but deterministic order, one
  `ExecutionReport(CANCELED)` each (reason from the command), then `MassCancelDone`. O(k) in the
  number of orders canceled for FIRM/SESSION/FIRM_SYMBOL scopes (per-firm order list).
- `ReferencePrice`: ignored unless `sourceTsNs` is newer than the last applied for the symbol
  (two consolidators submit the same updates). Applied: `ReferencePriceApplied` with the new band.
- `SymbolDefinition`: creates the symbol (books empty, `initialState`) or updates its parameters; `SymbolDefined`.
- `DayRollover`: expires every order, clears dedupe and intraday risk usage and positions, sets
  every symbol to `PRE_OPEN`; `DayRolled`.
- Malformed or unknown template: `CommandRejected(MALFORMED)`.

Engineering requirements
- One thread, no locks. No allocation on the steady-state order path (preallocated pools, Agrona
  primitive collections). Price levels indexed by tick around the reference price with intrusive
  FIFO queues; `orderId -> order` and `(firm, clOrdId) -> order` lookups in O(1).
- Never iterate a collection whose order depends on identity hash codes when the order is observable.
- Snapshot must round-trip exactly: a machine restored from a snapshot must produce the same events
  and the same next snapshot as the original for any subsequent input.
- Registers `io.lmb.matcher.MatcherShardFactory` as a `ShardStateMachineFactory` service.

## 4. Cluster node and event stream (`cluster-node`, `cluster-client`)

- One JVM per member: media driver (embedded Java driver by default; external C driver in
  production via `lmb.aeron.dir` and `lmb.driver.embedded=false`), Archive, ConsensusModule and a
  ClusteredServiceContainer whose service wraps a `ShardStateMachine`.
- Cluster time unit is **nanoseconds**. Ingress messages are raw SBE commands.
  `logPosition` passed to the machine is the Aeron log position of the entry.
- Member count comes from `Topology.membersPerShard()`: 3 in production (tolerates one failure),
  2 in the local profile (replicates, but both must be up), 1 allowed for tests.
- **Every member materialises the event stream**, not only the leader: the service publishes the
  machine's events to a local publication that the member's Archive records. Because the machine is
  deterministic, all members hold the same stream. On restart, events already recorded
  (`eventSeq <= last recorded`) are not appended again while the log replays.
- Consumers never see Aeron positions. They ask a member for "events after eventSeq N" over a small
  request channel (member base port + `EVENT_CONTROL_OFFSET`) and the member starts an Archive replay
  that follows the live recording. The client (`EventStreamClient`) drops duplicates by `eventSeq`,
  detects stalls and gaps, and fails over to another member, preferring the leader.
- `CommandClient` wraps an `AeronCluster` ingress session with leader redirect and reconnect.
- Snapshots contain the machine's chunks plus what the service needs (for example last event seq).
- `io.lmb.cluster.ClusterBackupMain` runs Aeron `ClusterBackup` for the DR region (asynchronous, so
  region loss has an RPO of seconds; this is stated, not hidden).
- Node port layout: `Topology.memberBasePort(shard, member)` + the `*_OFFSET` constants.

## 5. Services

All services are plain `main` classes on the shared classpath. Common conventions:

- Configuration: `Topology.load()` (file from `-Dlmb.topology` / `LMB_TOPOLOGY`) and `Config.get`.
  Identity: `lmb.shard.id`, `lmb.member.id` for cluster nodes, `lmb.instance.id` for everything else.
  Persistent state under `lmb.data.dir` (default `./data`), in a subdirectory named after the service and instance.
- Transport to shards only through `VenueClients.connect(topology, name)`.
- Print a single line `LMB_READY <service> <instance>` to stdout once serving. Shut down cleanly on SIGTERM.
- Logging through slf4j. Do **not** ship a `logback.xml` in a module's main resources (`common` ships the only one).
- Metrics: Prometheus HTTP endpoint on the port `Topology` assigns; names start `lmb_<module>_`.
  Latency as HdrHistogram-derived quantile gauges (p50, p99, p999, max).
- Reference data comes from `SymbolDirectory` / `FirmDirectory` (CSV files named in the topology).

|---|---|---|
| Shard node | `io.lmb.cluster.ClusterNodeMain` | 2 per shard / 3 per shard |
| DR backup | `io.lmb.cluster.ClusterBackupMain` | 0 / 1 per shard |

### 5.1 Gateway
- gRPC `OrderEntry.Session` (see `order_entry.proto`) and FIX 4.4 over Artio. `OrderQuery` unary calls for REST via Envoy.
- Session layer: Logon with firm, session id and API key checked against `FirmDirectory`; client and
  server sequence numbers; heartbeats; resume from `ShardCursor`s (replay from the event stream with `poss_dup`).
- Stateless checks before the log: symbol exists, required fields, max order size, per-session token
  bucket (`THROTTLED`), bounded per-shard in-flight queue (`UNAVAILABLE` when full or shard down).
  Cancels bypass the throttle and are prioritised over new orders.
- Routing by `SymbolDirectory` (ticker -> symbolId, shard). MassCancel fans out one command per shard.
- Reliability: every submitted command stays in an in-flight buffer until its effect appears in the
  event stream; on timeout or reconnect it is resubmitted with `possResend = TRUE`.
- Execution reports come only from the event stream, filtered by `sessionId`, so a client that
  reconnects to another gateway still gets its reports.
- Cancel-on-disconnect: `MassCancel(scope=SESSION, reason=DISCONNECT)` to every shard.

### 5.2 Market data publisher
- Consumes each shard's event stream; maintains books per symbol; publishes at `CommandApplied` boundaries.
- Binary incrementals over UDP (multicast in production, configurable unicast) on two independent
  feeds A and B with per-symbol sequence numbers; periodic snapshots carrying the sequence of the
  last applied incremental; TCP retransmission of missed sequences; gRPC `MarketData.Subscribe` with conflation.
- Its own SBE schema lives inside the module. Ships a client library that arbitrates A/B, detects gaps and recovers.

### 5.3 Feeds and NBBO
- `VenueFeedHandler` SPI (A/B line arbitration, gap detection, normalisation, receive timestamps);
  a simulated multi-venue feed over UDP for local use and tests.
- Consolidator: best bid and offer across non-stale venues (a venue silent or lagging beyond
  `lmb.nbbo.staleNs`, default 5 ms in production and looser locally, is excluded), reference price =
  NBBO midpoint rounded to tick, submitted as `ReferencePrice` to the owning shard, throttled per symbol.

### 5.4 Control plane
- PostgreSQL in production, H2 (PostgreSQL mode) for the local profile and tests (`lmb.db.url`).
- Bootstraps symbols and firms from the CSV files; pushes `SymbolDefinition` and `RiskLimitUpdate`
  to the shards and reconciles from the event stream.
- Admin REST (Javalin): halt/resume/auction per symbol or market-wide, kill switch, limits, day roll, status.
- Scheduler: trading calendar (pre-open, opening auction, continuous, closing auction, close) sent as
  `SymbolStateCommand` with `effectiveTimeNs`, so transitions are cluster timers.
- Risk-budget allocator: splits each firm's credit limit into per-shard budgets, rebalances from
  `RiskLimitApplied` usage; the sum of budgets never exceeds the firm limit.
- Two instances; only the holder of a database lock runs the scheduler and allocator.

### 5.5 Post-trade, replayer, tools
- Post-trade sinks are independent event stream consumers with persisted cursors: FIX drop copy
  (Artio), Kafka topics for clearing/surveillance, raw log and event segments to S3 with Object Lock,
  decoded events to ClickHouse. Each sink can be disabled (`lmb.posttrade.<sink>.enabled`); the local
  lite profile writes to files instead of external systems.
- Shadow replayer: reads the shard's Raft log from a member's Archive, runs the same
  `ShardStateMachine`, and compares each `CommandApplied.chainHash` with the live event stream.
  Divergence is a page-worthy metric. Backtester: same machine over a recorded log plus injected orders.

## 7. Build and test rules

- Build with `./mvnw` from the repository root (JDK 21 and Maven live under `.tools/`).
  Whole tree: `./mvnw -DskipTests install`. One module: `./mvnw -q -pl <module> test`.
- Tests must not need network access or Docker, must use unique temp and Aeron directories under
  the module's `target/`, small term buffers, and only ports from the module's test range:
  cluster-client 32000-32999, cluster-node 31000-31999, gateway 33000-33999, marketdata 34000-34999,
  feeds 35000-35999, controlplane 36000-36999, posttrade 37000-37999, replayer 38000-38999, tools 39000-39999.
- Each module documents itself in `docs/modules/<module>.md`: what it does, configuration keys,
  how to run it, known gaps.
